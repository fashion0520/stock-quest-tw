# 經驗紀錄

這份文件只記錄已在專案中實際觀察或驗證的做法，並標明可重用範圍。不要把原型簡化假設當成正式交易規格。

## E-001｜GitHub Pages 可承載無建置步驟的靜態原型

- **經驗**：單頁 HTML/CSS/JavaScript 可以由 Actions 直接打包根目錄並發布，無須先引入框架或建置流程。
- **未來適用範圍**：本專案的靜態介面、文件頁與小型學習工具。
- **界線**：需要機密 API key、登入、跨裝置同步或伺服器驗證時，不能把秘密放在靜態前端，應另設可信任後端。

## E-002｜示意行情要在每個關鍵位置清楚標示

- **經驗**：儀表板外觀像真實行情時，單靠頁尾聲明容易令人誤認。示意狀態要出現在行情總覽、個股／下單區與說明文字。
- **未來適用範圍**：所有股票報價、指數、圖表、報酬率與模擬成交價；未來可延伸成來源及更新時間欄位。
- **界線**：視覺標示不取代資料供應商授權。


## E-003｜交易計算用整數分、BigInt 中間值與不可變純函式

- **經驗**：價格、現金與成本基礎都存成整數分。乘上費率前使用 BigInt，按半入方式回到分；部分賣出按持倉成本比例分攤，最後清倉時把剩餘成本完整結清。交易引擎不改寫輸入帳戶，拒絕訂單以例外回報。
- **未來適用範圍**：模擬買賣、費用試算、平均成本、持倉損益和任何貨幣計算。
- **界線**：預設費率及取整是教學模擬，不是券商對帳或稅務計算；正式用途須由選定的產品規格與供應商規則決定。

## E-004｜本機帳戶資料需要 schema 驗證與失敗狀態

- **經驗**：localStorage 不一定可用，既存內容也可能毀損或版本不相容。載入回傳明確狀態（新帳戶、已載入、資料復原或儲存不可用），寫入前驗證 schema；儲存失敗不能阻止使用者繼續操作，但必須提示資料未保存。
- **未來適用範圍**：模擬帳戶、持倉、交易紀錄、觀察清單及遊戲進度；日後增加匯入／匯出或 schema migration 時可沿用。
- **界線**：資料只留在目前瀏覽器，清除網站資料可能永久刪除；不能存放真實券商密碼或敏感憑證。

## E-005｜純模組可用 Node 內建測試驗證交易邊界

- **經驗**：把交易引擎寫成不依賴 DOM 的 ES module 後，可直接用 `node:test` 驗證資金不足、超額賣出、費用、成本分攤、不可變狀態與本機儲存錯誤，不用增加第三方測試套件。測試期望值本身也要用手算覆核，避免把錯誤算式寫成通過條件。
- **未來適用範圍**：交易規則、資料驗證、費用估算、儲存版本與損益計算。
- **界線**：單元測試不會驗證瀏覽器版面、互動操作、跨裝置保存或 Pages 網路部署。

## E-006｜預估與成交共用同一份交易計算

- **經驗**：下單預覽與送單必須共用費用試算函式，才能避免畫面顯示的扣款與帳戶實際扣款不同。UI 先停用不合法訂單，純函式引擎仍需再次驗證，避免只靠前端限制保護狀態。
- **未來適用範圍**：所有買賣方向、費率設定、股數欄位、持倉操作及未來的委託確認頁。
- **界線**：目前按靜態參考價立即模擬成交，沒有即時撮合、滑價、委託簿或券商端狀態。

## E-007｜金融摘要需避免整元顯示造成不一致

- **經驗**：測試買入後發現，把現金和總資產四捨五入到整元，會讓資產變化與交易費看起來不一致；小幅負報酬也可能顯示成 `-0.00%`。帳戶摘要以分顯示，百分比小於半個顯示刻度時呈現 `0.00%`，保留底層精確值。
- **未來適用範圍**：現金、費用、成本、持倉市值、損益與總報酬等金融摘要。
- **界線**：顯示精度只處理可讀性，不能取代正式產品的財務取整規則或實際券商帳務。
